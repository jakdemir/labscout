How the ranking works

  1. Roster pulled from the organizers’ public team sheet. Emails are used for matching only and never published.
  2. GitHub identity first: an account whose public email matches the registration, or whose handle and name match the LinkedIn slug.
  3. Then the same founder-signal sources as Scout: GitHub, Hugging Face, PyPI/npm, Hacker News, YC, ORCID, NSF, NIH, arXiv, SEC Form D, NY corporations and more.
  4. Strict matching. Common names (25+ ORCID namesakes) keep only handle-verified evidence. Company registries count only when the filing names the attendee’s own company.
  5. Score is 0–100 from six capped components. Verified public evidence: 65. Builder (35): GitHub repos scored by log stars + forks, weighted by recency (last push ≤ 90 days 1.0, ≤ 1 year 0.7, older 0.4), plus packages by log downloads and language range. Traction (15): grants, filings, launches, YC, weighted by founder-signal stage. Identity (15): GitHub verified by registration email or LinkedIn handle (10) or by name + affiliation (6), other profiles, LinkedIn.
  6. Self-reported roster fields: 30, shown in grey. Role (20): founder / CEO / CTO 17, senior or founding builder 13, researcher 12, engineer 11, product 9, student 8, investor 6, plus 2 for an AI/ML title. Skills (10): weighted, plus 2 for a builder + go-to-market mix.
  7. Team (5): average verified evidence of your teammates, scaled to the strongest team.
  8. Every component saturates (diminishing returns), so one viral repo cannot dominate. Tiers come from rank percentile. Hover a rank for the percentile, click a row for each component’s points.
  9. Team score = sum of the top 3 member scores.
